# 跨服务事务采用"短链路 Seata AT + 长流程 Outbox/事件补偿"混合策略

Status: accepted

一期要正式落地 Kafka 事件流（入库→生成应付/发票、付款→订单结清等），而 Seata AT 全局事务与"发消息"存在一致性缺陷：全局事务提交后消息才发出，若消费失败无法回滚。决定采用混合策略：强一致短链路（如审批通过+预留库存）保留 Seata AT；长流程最终一致采用"本地事务 + Outbox 表 + Kafka + 幂等消费 + 重试/死信队列"。事件规范（topic 命名、payload schema、幂等键、死信）一并补齐。

## Considered Options

- **全部 Saga/事件补偿（去掉 Seata）**：架构统一、性能好；但一期所有跨服务操作都要设计补偿逻辑，工作量与出错面显著增加。
- **全部 Seata AT（延续现状）**：实现最简单；但高频/长链路存在锁与性能问题，且与事件流天然冲突（消息无法随事务回滚）。

## Consequences

- Kafka 事件驱动真正落地，Outbox 保证本地事务与消息一致。
- Seata 范围收敛到少数短链路，长链路依赖最终一致。
- 消费方必须幂等（幂等键=业务单号），失败进重试/死信。
