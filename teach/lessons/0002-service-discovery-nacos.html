Nacos 服务注册与发现

Lesson 0002 · 预计阅读 7 分钟

没有注册中心会怎样？

假设你要让 purchase-service 调 inventory-service。最简单的做法：在 application.yml 里写死 http://10.0.0.5:8084。然后某天运维重启了 inventory-service，IP 变成了 10.0.0.8——崩了。再加两台实例扩容，你得手动改配置加上 10.0.0.9 和 10.0.0.10——运维噩梦。

服务注册与发现解决的就是这个问题：服务的地址不再是静态配置，而是一个动态的、由注册中心维护的实时列表。

Nacos 的两重身份

Nacos 在这个项目里同时扮演两个角色，从配置里能直接看出来：

角色做的事配置项
注册中心 服务启动时注册自己，下线时注销。其他服务通过服务名查到所有实例。 spring.cloud.nacos.discovery
配置中心 把各服务的 application.yml 托管到 Nacos，支持动态刷新，不需要重启。 spring.cloud.nacos.config

看 auth-service 的配置 —— 它是项目里唯一一个同时用了 discovery 和 config 的服务：

spring:
   cloud:
     nacos:
       discovery:           ← 注册中心
         server-addr: localhost:8848
         namespace: dev
       config:              ← 配置中心
         server-addr: localhost:8848
         namespace: dev
         shared-configs:
           - data-id: common-config.yml
namespace 是 Nacos 的隔离单元。所有服务都配了 namespace: dev，意味着它们处于同一个逻辑环境。生产环境应该配 namespace: prod，这样 dev 的服务发现不到 prod 的服务，不会串。

一个服务从启动到被发现

以 purchase-service 为例，看完整的注册流程：

1. purchase-service 启动 2. 读取 application.yml: spring.application.name = purchase-service 3. 连接 Nacos (localhost:8848, namespace: dev) 4. 向 Nacos 注册: { 服务名: purchase-service, IP: 本机, 端口: 8083 } 5. 每隔 5 秒发心跳给 Nacos（临时实例） 6. Nacos 上可以看到 purchase-service 的状态为 UP

所有 6 个服务都配了同样的 Nacos 地址和 namespace：

# 每个服务的 application.yml 里都有这一段
spring:
  cloud:
    nacos:
      discovery:
        server-addr: localhost:8848
        namespace: dev

Gateway 怎么利用服务发现

回头看第一课里提过的 gateway 路由配置：

cloud:
  gateway:
    routes:
      - id: purchase-service
        uri: lb://purchase-service    ← 关键：不是 http://ip:port
        predicates:
          - Path=/api/v1/orders/**

lb://purchase-service 的执行过程：

  1. Gateway 收到 /api/v1/orders 请求，匹配到 purchase-service 路由
  2. 解析 lb://purchase-service → 从 Nacos 查询名为 purchase-service 的实例列表
  3. Spring Cloud LoadBalancer 从列表中选一个实例（默认轮询）
  4. 把请求转发到该实例的 /api/v1/orders

你可以在 Nacos 控制台看到一切

打开 http://localhost:8848/nacos（默认账号密码 nacos/nacos），进入「服务管理 → 服务列表」，选择 namespace 为 dev，你会看到：

服务名实例数健康状态
gateway-service1true
auth-service1true
supplier-service1true
purchase-service1true
inventory-service1true
payment-service1true

点进任何一个服务，可以看到实例的 IP、端口、权重、元数据。如果关掉一个服务，等几秒它就会从列表里消失（心跳超时）。

依赖在哪

每个服务 pom.xml 里都有这一行：

<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>

版本由父 POM 的 spring-cloud-alibaba-dependencies BOM 统一管理，不需要手写。

关键启示：Nacos 的本职工作是解耦服务的物理地址和逻辑标识。调用方只需要知道"我要调 inventory-service"，不需要知道它在哪台机器上。这为动态扩缩容、故障转移、蓝绿部署铺平了路。
